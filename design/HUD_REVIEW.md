# 공터서바이버 HUD 개선 검토

> 후속 사용자 지시 반영: PC 브라우저도 모바일처럼 세로 화면으로 표시한다. 실제 구현은 PC 9:16 중앙 화면 안을 맵으로 채우며 HUD·메뉴도 화면 너비에 맞춘다. 아래 초기 전체 브라우저 확장 제안보다 이 후속 지시가 우선한다. 구현·검증은 [HUD 구현 검증](HUD_IMPLEMENTATION.md)을 따른다.

2026-11-05. 현재 실행 화면과 코드, 다른 게임의 공개 플레이 스크린샷을 비교한 제안이다. 게임 구현은 변경하지 않았다. 다른 게임의 관찰은 아래 링크의 캡처에 한정하며 최신 버전의 모든 메뉴를 직접 플레이한 결과는 아니다.

## 선택한 방향

**화면 전체를 전장으로 쓰고, 체력·생존 시간·작은 처치 수·메뉴만 겹쳐 표시한다. 플레이어 스탯과 환경설정은 전투가 정지하는 메뉴 안에 모은다.**

전투 화면은 공간과 적의 움직임을 보는 화면, 메뉴는 수치를 읽고 조작하는 화면으로 역할을 나눈다. 현재의 원형 캐릭터·어두운 녹색 공터와 간결한 형태를 기준으로 한다. 이전 프로젝트 ‘들켰다’의 학교·칠판·증강·세트 UI를 이 게임에 도입하지 않는다.

## 전투 HUD

배치 개념이며 실제 픽셀 규격이나 완성 시안은 아니다.

```text
┌──────────────────────────────────────────────────────┐
│ 체력 ━━━━━━━ 3 / 3       00:42              ⚙ 메뉴  │
│                         처치 18                      │
│                                                      │
│                                                      │
│                 화면 전체가 전장                     │
│                                                      │
│                                                      │
│     터치한 위치에만 이동 조이스틱                     │
└──────────────────────────────────────────────────────┘
```

- 체력: 왼쪽 위에 짧은 가로 막대와 현재/최대 숫자를 함께 둔다. 흡혈로 회복한 소수 값도 기존 표기 규칙으로 유지한다. 위험 상태는 막대 색·숫자·테두리로 알리고 반복 점멸은 기본으로 쓰지 않는다.
- 시간: 중앙 위에 `00:42`처럼 고정 폭 숫자로 표시한다. 실제 전투 시간으로 계산하고 메뉴·탭 이탈 중에는 늘어나지 않는다.
- 처치: 시간 아래 한 줄의 작은 보조 정보로 둔다. 체력이나 적보다 눈에 띄게 만들지 않는다.
- 메뉴: 오른쪽 위에 실제 DOM 버튼을 둔다. 톱니 아이콘에 ‘메뉴’ 문구를 붙여 스탯·정지 기능도 포함한다는 점을 드러낸다. 최소 44×44 CSS px의 터치 영역과 키보드 포커스를 보장한다. Esc로도 같은 메뉴를 연다.
- 배경: 글자와 막대 뒤에 필요한 만큼만 짙은 바탕을 깐다. 큰 패널, 전체 폭 헤더, 긴 설명은 두지 않는다.
- 터치: 아래쪽은 버튼 없이 비워 둔다. 메뉴 클릭을 캔버스 드래그로 전달하지 않는다. 노치·홈 인디케이터 안전 영역을 반영한다.
- 현재 없는 경험치 바, 스킬 슬롯, 미니맵, 증강·세트·재화는 이 작업의 HUD에 추가하지 않는다.

## 메뉴와 스탯의 흐름

메뉴를 눌렀을 때는 간단한 행동 목록부터 보여준다. 아직 8개 기본 스탯 외에 읽을 정보가 많지 않아, 처음부터 큰 스탯 패널을 여는 것보다 정지와 복귀가 명확한 편이 낫다.

```text
메뉴 / Esc → 일시 정지
              ├ 계속하기 → 전장으로 복귀
              ├ 플레이어 스탯 → 8스탯 → 메뉴로 돌아가기
              ├ 환경설정 → 지원하는 설정 → 메뉴로 돌아가기
              └ 다시 시작 → 진행 초기화 확인 → 새 게임
```

- 배경에는 멈춘 전장을 남기고 살짝 어둡게 한다. ‘일시 정지’를 명확히 표시하며 과한 블러는 쓰지 않는다.
- PC는 중앙의 작고 읽기 쉬운 시트, 좁은 모바일은 여백을 줄인 시트로 쓴다. 긴 내용은 시트 안에서만 스크롤하고 제목과 복귀 버튼은 유지한다.
- ‘계속하기’를 가장 먼저, 가장 명확하게 둔다. ‘다시 시작’은 보조 행동으로 분리한다.
- 스탯·설정에서 Esc를 누르면 메뉴로 한 단계 돌아간다. 메뉴에서 Esc 또는 계속하기로 복귀한다. 바깥 배경 클릭으로 갑자기 전투를 재개하지 않는다.
- 닫힐 때 메뉴 버튼으로 포커스를 돌려준다. 이동 키·터치 캡처는 해제하고 새 이동 입력으로 조작을 이어가게 한다.
- 브라우저 포커스 복귀만으로 사용자가 열어 둔 메뉴를 해제하지 않는다. 현재 자동 정지와 사용자 메뉴 정지를 별도로 추적해야 한다.

### 플레이어 스탯

현재 있는 8스탯을 유지한다. 목록의 이름과 값은 두 열로 정렬하고 분류 제목만 작게 붙인다. 큰 카드 여덟 개나 의미 없는 아이콘은 필요하지 않다.

| 분류 | 표시 항목 | 현재 기본 표기 예 |
| --- | --- | --- |
| 공격 | 공격력 / 공격 속도 / 치명타 확률 / 치명타 피해량 | 1 / 2.5회/초 / 0% / 200% |
| 생존·이동 | 최대 체력 / 이동 속도 / 크기 / 피해 흡혈 | 3 / 180px/초 / 1배 / 0% |

HUD의 ‘현재 체력’과 스탯의 ‘최대 체력’을 명확히 구별한다. 흡혈은 ‘실제로 준 피해에 비례해 체력을 회복’이라는 짧은 설명을 제공한다. 현재 크기는 1배 표기를 유지한다. 단위를 바꿀 경우 실제 계산·표시·문서가 일치해야 한다.

### 환경설정

현재 실제로 있는 기능만 노출한다. 공터서바이버에는 소리 시스템이나 카메라 흔들림 설정이 없으므로 작동하지 않는 음량·흔들림 토글을 만들지 않는다.

- 조작 안내: 방향키 / 터치 드래그 / 자동 사격 / Esc 메뉴.
- 전체 화면: 지원하는 브라우저에서 켜고 끈다. 브라우저 안을 가득 채우는 기본 레이아웃과 운영체제 전체 화면 모드는 구별한다.
- 피격 효과 줄이기: 현재 피격 색 변화·처치 플래시를 줄이는 기능을 실제로 구현할 때 제공한다. 적중과 위험을 구별할 정보는 유지한다.
- 소리가 나중에 추가되면 그때 음량·무음을 추가한다.

## 전체 화면 구현에서 함께 해결할 부분

현재 월드는 360×640이고 Phaser는 FIT 모드다. CSS의 너비·높이를 100%로 바꾸는 것만으로는 요구를 충족하지 못한다.

1. 컨테이너는 100dvw×100dvh를 사용하고 페이지 스크롤을 없앤다.
2. 화면 비율에 맞춰 렌더 영역과 카메라·맵 경계를 함께 설계한다. 원형 캐릭터가 타원으로 늘어나거나, 단순 확대 때문에 경계·적이 잘리는 방식은 피한다.
3. 맵 경계·적 스폰 지점·이동 입력 좌표가 같은 공간을 참조하게 한다. 회전·창 크기 변경 후 몸이 경계 밖에 남지 않게 처리한다.
4. 가로로 보이는 공간이 넓어지면 회피 공간·적 밀도·사거리의 체감이 달라진다. UI 구현과 별도로 실제 전투를 비교해 확인한다.
5. 메뉴 정지는 물리·스폰·사격·피해 쿨다운·피격 연출·생존 시간에 모두 적용한다. 현재 `setPaused` 기반을 확장하되 포커스 정지와 겹치는 상황을 처리한다.

## 구현 후 확인할 기준

- 1440×900 PC, 390×844 세로, 844×390 가로에서 전장이 화면을 채우며 원형 캐릭터의 비율이 유지된다.
- HUD끼리 겹치지 않고 모바일 안전 영역을 침범하지 않는다.
- 스탯을 열어도 페이지 스크롤과 레이아웃 이동이 생기지 않는다.
- 메뉴·하위 화면·탭 이탈 중 전투와 시간이 멈추고, 탭 복귀로 메뉴가 자동 해제되지 않는다.
- 닫기·다시 시작·화면 회전·pointercancel 뒤 이동 입력이 남지 않는다.
- 키보드만으로 메뉴·스탯·설정·복귀가 가능하다.
- 다시 시작은 확인을 거치고 게임 오버에서는 기존 재시작 흐름과 충돌하지 않는다.
- 자동 검증과 빌드 통과에 더해 가로·세로의 실제 전투를 비교한다. 그것을 재미·밸런스 검증 완료로 표현하지 않는다.

## 이번 조사 범위

공터서바이버의 HTML·CSS·Phaser 초기화·입력·정지·스탯·피드백 코드를 읽고 세 화면 크기를 브라우저에서 확인했다. 다른 게임 네 개의 공개 플레이 캡처를 시각적으로 확인했다. 조사용 캡처와 이 문서만 추가했으며 제품 코드는 수정하지 않았다. 새 구현이 없으므로 이 검토에서 빌드·테스트는 실행하지 않았다.
