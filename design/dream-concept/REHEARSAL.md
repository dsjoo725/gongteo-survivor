# Rehearsal: 아직, 꿈 v0.7

## v0.7 선택된 3안 — 달빛의 공터

- 사용자 선택: 세 아트 방향 중 3번. 선택된 청록색 밤 페인팅을 전투·정지·타이틀에 적용했다.
- 전투 페인팅에서 UI를 제거하고 네이티브 버튼·타이머·처치·체력·조이스틱을 따로 구현했다. 캐릭터·적·공격 표현은 정지 장면 안에 남아 있다. 주아체 36px 타이머와 Pretendard를 사용한다.
- 내장 image_gen으로 전투 장면, 같은 세계의 타이틀 배경, 투명 회분홍 붓자국을 만들었다. 독립 검토에서 노치 모의 화면의 달과 정지가 겹친 문제를 발견해 달의 위치와 배경 상단 여유를 수정했다. 320px와 안전 영역 프레임을 다시 확인해 해소됐다.
- 모바일: 320×568·360×640·390×844·412×915 전체 화면과 넘침, 48px 정지 타깃, 정중앙 시간·간격, 안전 영역 상단 44/하단 34/좌우 8px 모의 값, 누름 위치 유지, 터치 메뉴 진입·설정·복귀 8항목 통과. [결과](../../artifacts/dream-mobile-checks-v7.json).
- 기존 보드 동작 13항목, TypeScript 검사, 정적 빌드 통과. 1440px 보드·390px 개별 전투의 stageshow 정지 gate: `no-issues-detected`, `rehearsal passed`. 정지 촬영으로 모션을 판정하지 않았다.
- 독립 시각 검토에서 타이틀·메뉴 글자 잘림과 체력 겹침은 없었다. 수정 뒤 320px·안전 영역의 달/정지 분리와 캐릭터/체력 중심축을 재확인했다.
- 주요 이미지: `dream-concept-board-v7.png`, `dream-combat-mobile-390-v7.png`, `dream-combat-mobile-320-v7.png`, `dream-combat-mobile-safe-v7.png`, `dream-pause-mobile-v7.png`.

## v0.5 창틀 HUD와 모바일 화면

- 사용자 요청: 분석한 탕탕특공대의 접합 디테일을 꿈속 콘셉트의 정지 탭·시간·처치에 적용하고 모바일을 우선한다.
- 창틀과 세 표시의 얇은 선·윗면 빛·아래 두께를 공유했다. 정지는 왼쪽에서 이어지는 회분홍 탭, 시간은 위 창틀에서 내려온 판, 처치는 오른쪽에 물린 기록 띠다. 정지 누름은 면색과 그림자를 바꾸며 타깃·아이콘은 고정한다.
- 개별 화면은 실제 가용 뷰포트를 채우고 UI와 배경 배율을 분리한다. `viewport-fit=cover`와 `env(safe-area-inset-*)`를 적용했다. 비교 보드와 이전에 선택한 여자 캐릭터·주아체 + Pretendard는 유지했다.
- Chrome의 터치 모의 환경: 320×568·360×640·390×844·412×915에서 화면 채움·넘침·48px 정지 타깃·정중앙 시간·최소 간격 확인. 안전 영역 상단 44·하단 34·좌우 8px 모의 값, 누름 중 타깃 위치 유지, 터치 정지→설정→메뉴→복귀까지 8항목 통과. [결과](../../artifacts/dream-mobile-checks-v5.json).
- 기존 보드 동작 확인 13항목, TypeScript 검사, Vite 정적 빌드 통과.
- 1440px 비교 보드와 390px 개별 전투 화면의 stageshow 정지 gate: `film: no-issues-detected; still capture only, motion was not judged`, `rehearsal passed`. 844px 높이의 터치 화면은 별도 `capture-mobile.mjs`로 촬영했다.
- 독립 검토: 보드·390px·320px·안전 영역·정지 화면 5종. 상단 접합·시간 정렬·작은 화면에서 중대한 문제는 없었다. 체력 숫자와 마름모 아이템이 겹친 지적을 받아 아이템을 오른쪽 아래로 옮겼고 재촬영으로 분리를 확인했다.
- 주요 이미지: `dream-concept-board-v5.png`, `dream-combat-mobile-390-v5.png`, `dream-combat-mobile-320-v5.png`, `dream-combat-mobile-safe-v5.png`, `dream-combat-mobile-pressed-v5.png`, `dream-pause-mobile-v5.png` (artifacts 폴더).
- 실제 게임 로직·이동 입력에는 적용하지 않았다. 실기기 Safari/Chrome, 손가락 가림, 이동과 메뉴의 제스처 중재·pointercancel, 전투 효과 밀집도·성능은 검증하지 않았다. 정지 화면 gate로 애니메이션 품질을 판정하지 않는다.

## 구성과 시작 예제

- Gold: stageshow `window-row`. 같은 높이의 세 화면을 비교하는 구조와 일정한 간격을 참고했다.
- 사용자 요청에 따라 타이틀·전투·정지 화면을 모두 보이게 했다. 제품 소개 애니메이션처럼 화면 가장자리를 자르지 않는다.
- Gold 촬영: `artifacts/dream-gold-reference.png`. 원본 예제에서 글자 윗부분 1px 잘림 경고가 발생했다. 이를 우리 시안의 통과 결과로 해석하지 않았다.
- 우리 환경은 직접 작성한 SVG이고 컨트롤은 Stage·Button을 사용했다. 전체 게임의 화풍이나 컴포넌트 API 확정을 뜻하지 않는다.

## 촬영과 동작 확인

- 비교 보드: 1440px에서 세 화면.
- 좁은 보드: 390px·320px에서 세로 배열과 텍스트 줄바꿈.
- 개별 시안: title·combat·pause, 각각 360×640 기준.
- 정지 화면 gate: 보드 1440px, 타이틀 390px, 정지 메뉴 390px.
- 실제 클릭 흐름: 진입, 정지, 스탯, Esc로 메뉴 복귀, 설정 토글, 계속하기, Esc로 정지, 재시작 확인, 타이틀 복귀, 미리보기 닫기와 포커스 복귀.
- 동작 감소: 완성된 정지 메뉴가 표시되는 것을 확인했다. 자동으로 반복되는 시연이나 전투 애니메이션은 만들지 않았다.

## Gate

최종 1440px 보드와 390px 타이틀·정지 화면:

```text
film: no-issues-detected; still capture only, motion was not judged
rehearsal passed (necessary, not sufficient: references/verify.md and the fresh eye in review.md still stand)
```

이 결과는 정지 시안의 검토 결과다. 애니메이션 루프·프레임률·라이브 게임 품질을 검증했다는 뜻은 아니다.

## 발견한 문제와 수정

- 네이티브 button으로 바꾼 뒤 원본 스타일 초기화가 컨트롤을 덮었다. 복사한 kit의 초기화에서 해당 Button을 제외해 모양과 네이티브 동작을 함께 유지했다.
- 전장 경계 선이 검정 삼각형으로 채워졌다. 해당 SVG 선의 채움을 제거했다.
- 위치 문구와 문 오브젝트가 겹쳤다. 문을 오른쪽으로 옮겼다.
- 정지 메뉴 버튼 간격과 작은 Esc 표기를 늘리고, 종이 패널의 여백을 정리했다.
- 배경은 SVG와 HUD의 밝기를 낮춰 정지 상태를 표현한다. 반투명 조작부 위에 다시 반투명 면이 겹쳐지는 중복 합성을 없앴다.
- 독립 검토에서 320px 푸터의 한국어가 조각나 줄바꿈되는 문제를 발견했다. 시각 방향 문구를 팔레트 위에 별도 행으로 배치했다.
- 후속 검토에서 종이 패널 하단의 여백이 과하다는 지적을 받았다. 정지 표면에 실제 kit Popover를 적용하고 패널을 내용 높이에 맞춰 줄여 메뉴와 Esc 안내 사이를 27px로 조정했다.

## 한계

실제 게임 시뮬레이션, 터치 이동, 실제 휴대폰, Safari, 게임 속 효과의 밀집도와 프레임률, 최종 아트·대비의 기기별 차이는 확인하지 않았다. 수치와 설정은 미리보기 데이터다. 외부 글꼴이 차단되면 시스템 글꼴로 대체된다.
