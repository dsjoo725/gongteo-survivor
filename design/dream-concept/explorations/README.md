# 꿈속 전투 HUD — 아트 방향 비교

**선택 결과:** 사용자가 3안 ‘달빛의 공터’를 선택했다. [현재 v0.7 적용 시안](../README.md)에 청록색 페인팅·크림색 정보·회분홍 정지 면을 반영했다. 아래 내용은 선택 전 비교 기록이다.

사용자 기준: **게임의 그림체와 세계관 안에서 자연스럽게 만들어진 느낌**. 단일 창틀 형태를 장식으로 보완하는 방향은 거절되었다. 캐릭터·배경과 HUD의 선, 재질, 빛을 함께 탐색한다. 코드 미리보기의 HUD를 새 방향으로 확정하지 않았다.

내장 image_gen 도구로 각각 별도 프롬프트를 사용해 생성했다. 입력은 기존 [전투 화면](../../../artifacts/dream-concept-combat-v5.png)의 캐릭터·장면 구성이며, 기존 창틀 HUD는 형태 참고에서 제외했다. 전체 프롬프트는 [prompts.json](prompts.json)에 보존한다.

## 참고 자료와 적용한 원리

- [Em Zhao — UI Art / Lost Words](https://emzhao.artstation.com/projects/EV32NN): 작가는 게임의 수채화 표현과 챕터별 팔레트를 아이콘에도 사용했다고 설명한다. 1안에서 그림과 정보 표현의 붓결·색을 공유하는 원리로 참고했다.
- [Katerina Kosiposha — Kudesy UI](https://katerinas.artstation.com/projects/QxzQKr): 작가 설명의 연필화·재질·자연색과 UI를 아우르는 공통 시각 언어를 참고했다. 개별 도형이나 문양은 복사하지 않았다.
- [Giovanna Amorim — Storybook RPG App Game UI](https://gamorim.artstation.com/projects/L3A8AK): 작가가 제시한 소박하고 귀여운 고전 RPG의 미감을 보조 참고했다.
- [Kirby’s Epic Yarn](https://www.nintendolife.com/reviews/wii/kirbys_epic_yarn): 직물·털실로 세계 전체를 일관되게 만드는 표현을 2안의 공통 재질 원리로 참고했다.
- [Bo and the Moonlit Blue Flower — 공식 매뉴얼](https://www.marv.jp/onlinemnl/bo/jp/switch/): 손으로 그린 달밤의 공간과 밝은 정보 대비를 3안의 보조 방향으로 참고했다.

핀터레스트 검색도 시도했으나 이번 검색에서는 확인 가능한 개별 핀 결과를 얻지 못했다. 확인한 작가 프로젝트와 게임 자료를 중심으로 방향을 만들었다. 특정 게임의 HUD나 아트를 재현하는 시안이 아니다.

## 세 방향

| 안 | 세계의 재료 | UI가 연결되는 방식 | 눈으로 확인한 장점 | 남은 점 |
| --- | --- | --- | --- | --- |
| 1 종이에 그린 낮잠 | 과슈·종이·따뜻한 민트 | 붓자국의 정지 면, 같은 안료 느낌의 숫자와 아이콘 | 기존 팔레트와 캐릭터에 가장 가까우며 별도 UI 판을 거의 쓰지 않는다 | 전체 종이 결이 강하다. 실제 게임에서는 질감 밀도와 적/공격 대비를 낮은 해상도에서 조정해야 한다 |
| 2 베갯속 꿈 | 솜·면·펠트 | 같은 천의 접힌 가장자리와 자수 | 배경·가구·인물·HUD의 재질 연결이 가장 분명하다 | 게임 전체 아트를 바꾸는 폭이 크고 상단 천의 면적이 넓다 |
| 3 달빛의 공터 | 청록 밤과 부드러운 페인팅 | 달빛과 같은 크림색 글자·단순한 조작 면 | ‘꿈속’의 몽환성과 살짝 불안한 분위기가 가장 강하다 | 상단 정지는 아직 독립된 색면이다. 후속 시안에서 배치·색·실루엣을 다듬어야 한다 |

세 장을 직접 확인했다. 캐릭터는 리본·밤색 머리·민트 드레스와 작은 점눈을 유지하지만 생성 과정에서 세부 실루엣 차이가 있다. 이는 그림체 탐색용이며 기존 캐릭터를 교체한 결과가 아니다.

UI 수치는 03:24, 처치 128, 체력 72/100을 공유한다. 생성 이미지의 글꼴은 정확한 주아체·Pretendard 구현을 보장하지 않는다. 선택한 방향을 실제 코드로 옮길 때 지정 글꼴·48px 터치 영역·안전 영역·실제 화면비를 적용한다. 입력 동작이나 실기기를 검증한 결과로 해석하지 않는다.
