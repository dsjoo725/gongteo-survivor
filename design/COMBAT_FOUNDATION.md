# 전투 기반과 확장 계약

## 현재 플레이 규칙

- 적은 기본 추격형 한 종류이며 최대 체력 2, 공격력 1, 공속 0이다.
- 기본 공격력 1의 명중 두 번으로 처치한다. 접촉 피해는 적 공격력이며 공속과 독립적이다.
- 접촉은 치명타·흡혈을 사용하지 않고 플레이어의 48틱 피격 보호를 공유한다.
- 작은 넉백, 0.1초 사망 축소, 약한 플레이어 피격 명도 변화만 사용한다. 동작 감소 설정은 사망을 페이드로 표현한다.
- 이번 작업은 성장·증강이 붙을 내부 경로를 구현한다. 새로운 적이나 성장 선택 화면은 추가하지 않는다.

## 스탯 변경

플레이어는 `{ kind: 'player', id: 0 }`, 적은 `{ kind: 'enemy', id }`로 참조한다. 새 기능은 `ArenaScene.combatRuntime`의 `CombatSession`을 사용한다.

- `setBase(ref, patch)`: 영구 성장 또는 기본값 교체.
- `upsertModifier(ref, { id, add, multiply, expiresAtTick? })`: ID가 같으면 교체한다. 같은 효과가 실수로 중복 등록되지 않는다.
- `removeModifier(ref, id)`: 효과를 제거하고 기본값에서 다시 계산한다.
- 계산식은 스탯마다 `(기본값 + 효과의 add 합) × 효과의 multiply 곱`이다. 효과 ID 순서로 계산하므로 등록 순서에 의존하지 않는다.
- 역연산으로 수치를 복구하지 않으므로 반복 장착·해제에 따른 누적 오차가 없다.
- 유효 범위를 벗어나는 변경은 기존 상태를 보존하고 예외를 반환한다. 예약된 효과 만료 뒤에도 유효한 조합인지 등록 시 검증한다.
- 만료 틱부터 효과가 사라진다. 메뉴·포커스 정지 중에는 전투 틱이 흐르지 않는다.
- 최대 체력이 늘어도 현재 체력을 늘리지 않는다. 줄면 현재 체력을 새 최대치로 제한한다. 죽은 대상을 되살리지 않는다.
- 장면 어댑터는 최종 스탯 변경을 감지해 플레이어·적의 몸체와 표시 크기, 경계와 군중 충돌, 이동 속도, 체력바와 스탯창을 갱신한다. 일시정지 화면에서도 갱신된다.
- 공속 변경 시 이미 쌓인 소수 공격 진행도를 보존한다. 공속 0은 발사를 멈추고, 다시 켜면 대기 공격 하나부터 시작한다.

확률·흡혈은 0~1, 치명타 배율은 1 이상, 최대 체력·크기는 양수이며 스탯의 수치 유효성은 공통 검증을 따른다. 효과가 이 범위를 넘으면 자동으로 조용히 제한하지 않고 변경을 거절한다.

## 공속과 탄환

고정 시뮬레이션은 60Hz이지만 공격 횟수에는 초당 60회 제한을 두지 않는다. 매 틱 공속/60의 공격 진행도를 누적한다. 대기 중에는 공격을 무제한 비축하지 않는다.

동일 틱의 여러 공격은 하나의 **묶음 탄환**으로 이동한다. 예를 들어 공속 120이면 2초 동안 240회의 공격을 최대 120개 발사 묶음으로 표현한다. 공속 1,000이면 2초 동안 2,000회를 보존한다. 탄환 하나가 가진 `remaining`은 아직 소비하지 않은 공격 횟수다.

- 공격력·치명타 판정·흡혈은 발사 시점에 불변 정보로 확정한다. 발사 뒤 성장하거나 버프가 만료돼도 기존 탄환에는 영향을 주지 않는다.
- 같은 틱에 묶인 공격은 경로와 치명타 판정을 공유한다. 개별 공격마다 서로 다른 치명타를 뽑는 방식은 아니다. 기본 공속에서는 기존처럼 탄환 하나가 공격 한 번이다.
- 체력이 남은 적은 필요한 공격 횟수만큼 피해를 받는다. 처치 후 남은 공격 횟수는 계속 이동해 다음 적을 맞힐 수 있다.
- 실제로 제거한 체력만 흡혈하며 과잉 피해는 회복·추가 처치 보상을 만들지 않는다. `hit.hits`에는 실제 대상에게 사용한 공격 횟수를 기록한다.
- 탄환 표현은 틱당 하나이며, 기본 수명 54틱에 맞춰 최대 55개를 확보한다. 테스트용 추가 탄환은 별도로 확보한다. 높은 공속에 비례해 물리 객체를 무제한 생성하지 않는다.

## 충돌 순서

물리 이동 전 탄환·적 위치를 보존하고, 이동·군중 보정 후 위치와 함께 상대 이동 선분을 검사한다. 가장자리 스침·작은 적·빠른 탄환·움직이는 적을 포함한다. 한 탄환의 대상은 이동 경로에서 먼저 만나는 순서로 정하며 같은 시점이면 적 ID 순서로 결정한다.

탄환 피해를 접촉 피해보다 먼저 처리한다. 처치된 적은 즉시 충돌에서 빠진다. 넉백이 발생하면 벽·군중·접촉을 다시 계산한다. 여러 적과의 접촉은 현재 생성 ID 순서의 첫 유효 공격력을 적용하고 플레이어의 공통 피격 보호를 사용한다.

## 공통 피해와 이벤트

`resolveDamage`는 순수 함수다. `CombatSession.applyAttack`은 결과를 대상에게 적용하고 실제 체력 감소에 따른 흡혈, 사망·처치를 한 경로로 처리한다. 체력이 이미 0인 대상에게 다시 피해를 넣어도 처치 보상을 중복 발생시키지 않는다.

이벤트는 실제 플레이에도 존재한다. 개발용 로그와 분리되어 있으며 `events.on(type, listener)` 또는 `events.subscribe(listener)`로 구독하고 반환된 함수로 해제한다.

| 이벤트 | 의미 |
| --- | --- |
| `attack` | 불변 공격 정보 생성, 묶음의 논리 공격 횟수 포함 |
| `hit` | 실제 피해, 사용한 공격 횟수, 대상과 피해 전후 체력 |
| `heal` | 상한을 적용한 실제 회복량 |
| `death` | 대상 사망 |
| `kill` | 공격 주체가 대상을 처치함 |
| `statsChanged` | 변경 전후 최종 스탯과 현재 체력 |

동일 피해의 이벤트 순서는 `hit → heal(발생 시) → death → kill(처치 시)`다. 이벤트와 공격·대상 참조는 불변 값이다. 이벤트는 판정 뒤 정해진 시점에 전달하며 구독 중 발생한 이벤트는 재귀 호출하지 않고 다음 전달 시점으로 넘긴다.

효과의 전투 반응은 `enqueue`로 다음 고정 틱에 예약한다. 렌더링 중 또는 이벤트 전달 중 적 목록을 직접 수정하지 않는다. 예약 명령은 피해·회복·기본 스탯 변경·효과 추가·제거를 지원한다. 이미 제거된 대상을 향한 명령은 무시한다. 세션 종료 시 구독과 예약 명령을 해제한다.

다음은 이후 증강 구현에서 사용할 수 있는 **예시**이며 현재 플레이에 활성화돼 있지는 않다.

```ts
const off = session.events.on('kill', event => {
  if (event.attack.source.kind !== 'player') return;
  session.enqueue({
    type: 'heal', source: event.attack.source,
    target: event.attack.source, amount: 0.5,
  });
});
// 해당 증강을 해제할 때 off(); 새 런은 새 세션에 다시 등록한다.
```

`hit` 효과는 `event.attack.kind`로 주 공격·접촉·파생 효과를 구분할 수 있다. 자기 자신이 만든 파생 피해가 같은 효과를 다시 발동하지 않도록 구독 측에서 종류를 선택한다. `CombatActor.statBlock` 직접 변경보다 세션의 변경 API를 사용해 체력 보정과 이벤트를 함께 유지한다.

## 검증 범위

도메인 검증은 공속 2.5~6천만의 공격량, 비축 방지, 이동 경로 충돌, 스탯 교체·만료·원자적 거절, 최대 체력 규칙, 공격 스냅샷, 실제 흡혈·중복 처치 방지, 구독 해제·재귀 방지·다음 틱 반응을 검사한다.

브라우저 통합 검증은 리뷰에서 재현한 스침·작은 적 통과, 빠른 탄환의 첫 대상 선택, 공속별 실제 공격량과 표현 수, 남은 공격의 이동, 발사 후 성장, 스탯창·충돌체 동기화, 적 스탯 변경, 처치 회복 확장·정지·재시작을 검사한다. 기존 기본 2타 처치·접촉·군중·HUD·모바일 입력 테스트도 유지한다.
